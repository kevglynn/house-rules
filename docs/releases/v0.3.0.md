# v0.3.0: brand cohesion

Decision 0001 settled the kit's name and v0.2.0 shipped it, but the tooling layer still spoke a third brand: `playbook-init.sh`, `playbook-doctor.sh`, `pbi`/`pbd` aliases, `~/.playbook-*` dotfiles, and "the playbook" throughout the active docs — 463 lines across 66 kit files, plus the rendered artifacts on every machine and target repo that teach agents all of it. v0.3.0 retires that brand in one coordinated cut, so no artifact generation mixes the two vocabularies. The five decisions (A1–A5) are recorded in [docs/decisions/0002](../decisions/0002-brand-cohesion-tooling-rename.md).

## One dispatcher

`scripts/house-rules` is now the sole documented entry point:

```bash
bash "${PROCESS_KIT:-$HOME/process-kit}/scripts/house-rules" init --tool cursor|claude|both
bash "${PROCESS_KIT:-$HOME/process-kit}/scripts/house-rules" doctor --agent
bash "${PROCESS_KIT:-$HOME/process-kit}/scripts/house-rules" sync --format all
hr doctor    # with the installed alias
```

The implementation scripts were renamed (`playbook-init.sh` → `init.sh`, `playbook-doctor.sh` → `doctor.sh`) and remain independently runnable; the dispatcher forwards arguments unchanged via `exec`, so doctor's exit codes and `SUMMARY:` contract pass through untouched. The `hr` and `house-rules` aliases replace `pbi`/`pbd`.

## Machine state, clean break

The dotfiles renamed: `~/.house-rules-sync-targets`, `~/.house-rules-aliases.sh`, `~/.house-rules-ignore`. No legacy-name recognition ships in code — the audience is one maintainer plus agents, the field was re-rendered in the same session, and the just-retired 0.2.0 migration window (process-kit-0em/26b) demonstrated what a lingering compatibility layer costs. Because the rc block's sourced filename changed, the aliases installer gained a content-aware refresh: a present-but-stale block is rewritten in place instead of being reported as "already installed."

What deliberately did **not** change: the `PROCESS_KIT` env var, the `~/process-kit` clone path, and the `process-kit-*` bead-ID prefix stay as documented history (A3), and dated records — CHANGELOG, decision docs, research notes, the beads ledger — keep "playbook" as historical fact (A4).

## The review paid for itself

The wave-level Tier 1 review (four parallel lenses) found a Critical the fixture suite's existing malformed-marker cases missed: an orphan BEGIN sitting above a well-formed marker block made all three installers' rewrite scanners open at the orphan, swallow the real block and every user line in between, and pass the truncation guard — silently deleting shell config or `~/CLAUDE.md` content. The refresh path shipped in this very wave made that state reachable from a plain install run. It was reproduced live, fixed test-first at every scanner (17 red assertions → green, `.tdd-ledger.jsonl` carries the pair), and the same commit made guard refusals exit nonzero instead of hiding behind success banners. The suite now carries 55 assertions including CRLF, nested-marker, and rendered-content cases.

## Upgrade notes

For machines that ran the 0.2.0 installers:

- Re-run `install-aliases.sh` — it writes `~/.house-rules-aliases.sh`, refreshes the rc block in place, and installs `hr`/`house-rules`. The old `pbi`/`pbd` aliases and `~/.playbook-aliases.sh` are orphaned, not migrated; delete them when convenient.
- Move `~/.playbook-sync-targets` to `~/.house-rules-sync-targets` by hand (one `mv`); sync-rules fails loud with a template if the new file is missing. `~/.playbook-ignore`, if you used it, becomes `~/.house-rules-ignore`.
- Re-run `install-global-safety-net.sh` and re-init target repos (`hr init`) to re-render the `~/CLAUDE.md` blocks and AGENTS.md sections in dispatcher form; the doctor's version-stamp check flags any straggler.
