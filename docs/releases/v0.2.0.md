# v0.2.0: first public release

v0.2.0 is the kit's first public release, published under the name **house-rules**. The working name during incubation was process-kit; the repository rename happens at the release cut, and old clone URLs redirect. Everything below summarizes the arc from v0.1.0 (2026-07-15, the fresh-history extraction from a private predecessor) to this cut.

## Flagship: profile-driven conventions

The kit's conventions used to live in two places at once: prose rules that agents read, and checker CLIs that enforce the same conventions mechanically. Two homes for one convention means they drift, and drift here is silent: the rule says one thing, the checker enforces another, and agents split the difference.

v0.2.0 closes that gap for the highest-traffic conventions:

- **`profiles/conventions.toml`** is the machine-readable source for the Tier 1 convention sets: commit types and branch grammar, close-evidence requirements, the defer-comment grammar, the banned-token catalog, and TDD obligations by bead type. Plain TOML, parsed with stdlib `tomllib`, no dependencies.
- **`scripts/conventions`** is the CLI over it: `check-commit`, `check-branch`, and `check-close` answer verdicts in JSON with stable exit codes, and `render-rule` projects the profile into the exact prose that lives in the rules.
- The affected rule sections (git conventions in `operating-model`, the evidence table in `bead-completion`, the defer law in `defer-convention`, the token catalog in `agent-identity`, the obligations table in `pragmatic-tdd`) are now **generated fragments**, marked as such in the rule files and byte-checked against the profile render.
- A **CI regen gate** fails the build when a committed fragment diverges from the profile render, with a seeded-drift self-test proving the gate actually fires.
- The profile **ships to target repos** with the checkers and is drift-checked byte-for-byte by the doctor (SUMMARY key `profile_drift`). In targets it is kit-owned and the checkers run advisory; blocking enforcement stays in the kit's CI.

Editing a convention now means editing the profile. The rule text and the checker verdicts both follow from it, and CI refuses the state where they disagree.

## Also in this release

**Rule topology: thin law plus skills.** A kit-wide mechanism-placement audit split the heavyweight rules into always-on law cores and on-demand procedure skills: `operating-model` + `graph-planning`, `bead-completion`/`beads-quality` + `bead-authoring`, `pragmatic-tdd` (rule + skill), `multi-agent-review` + `tier1-review`/`tier2-handoff`, `defer-convention` + the `defer-lint` checker. Agents carry less always-on text and load the procedure at the moment it applies.

**Checker CLI suite.** Four stdlib-only, single-file Python CLIs now enforce what the rules prescribe: `tdd-ledger` (durable red-then-green evidence), `defer-lint` (deliberate simplifications need a ceiling and an upgrade trigger), `close-reason-lint` (close reasons need commit refs and AC mapping), and `banned-token-scan` (the agent-identity rule's no-human-estimation classes). All four ship to target repos via a single manifest (`scripts/distributed-clis.list`), and the doctor drift-checks each one against the kit copy. The three convention checkers read `profiles/conventions.toml` where present and carry test-pinned fallback grammars for profile-less trees.

**Kit CI self-enforcement.** The kit runs the checks its doctrine prescribes: a projection-drift gate (generated `claude/rules/` must match the `cursor/rules/` canon), shellcheck at warning severity, and the new profile regen gate. Every gate carries a seeded-drift self-test so a silently broken gate fails loudly.

**Refinement framework.** A deliberate, evidence-grounded audit loop for the kit's own mechanisms: the `refinement` skill, a concepts doc, and a proposal template. The kit-wide mechanism-placement refinement that produced the rule topology above was its pilot.

**Publication readiness.** Apache-2.0 LICENSE with CONTRIBUTING refreshed to match; installer marker blocks migrated from the legacy `ai-dev-playbook:` prefix to `house-rules:` with in-place migration of already-installed blocks; a neutrality audit moved per-user voice parameters out of the public core behind an overlay mechanism; the lazy-senior-dev skill family was renamed to `graybeard-*` with credit to [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail) (MIT), which it was adapted from; naming, license, and publication posture are recorded in `docs/decisions/0001` with dated amendments.

**Governance.** The Agentic Covenant ships as the kit's CODE_OF_CONDUCT: a code of conduct written for communities where humans and AI agents collaborate, with AI-assisted contributions explicitly welcome and disclosed.

## Upgrade notes

For machines that tracked the incubating repo:

- Re-run `install-global-safety-net.sh` and `install-aliases.sh`. Both recognize legacy `ai-dev-playbook:` marker blocks and rewrite them in place under the new prefix; nothing duplicates.
- Re-running `playbook-init.sh` (or the next rules sync) migrates a target repo's `AGENTS.md` marker section the same way.
- The `ponytail-*` skills are now `graybeard-*`. Machine-global skill copies need a re-copy; project-local copies refresh on the next init with `--skills`.
- The repository renames from `process-kit` to `house-rules` at the cut. GitHub redirects existing remotes; update them when convenient.
